## DotNet.OllamaHub 项目立项调研 + 方案（待用户确认，未开始编码）

产出：`PLAN.md`（工作区根目录）。

### 核心技术结论
- **不需要写 IDE 插件**。VS 2026 (18.6.0+) 与 VS Code (1.113+ / Copilot Chat 0.41+) 的 Copilot Chat
  已内置 **Ollama 提供程序**，路径：模型下拉 → 管理模型 → Ollama → 端点 `http://localhost:11434`。
  所以只要做一个伪装成本地 Ollama 的 HTTP 服务即可。
- BYOK/BYOM 只覆盖 Chat / Agent / Plan，**不覆盖行内代码补全**（官方限制）。
- 国内模型（DeepSeek/通义/Kimi/GLM/硅基流动/火山方舟/混元/MiniMax/ModelScope）几乎全是
  OpenAI 兼容 `/v1/chat/completions`，P0 只做 OpenAI 兼容上游即可覆盖 90%。

### 竞品
- `mingkuang-Chuyu/OllamaHub`（C#，主要参考，无服务化）
- `shunnet/CopilotProxy`（Node/Bun + WPF，功能最全但**已停更**，只支持 DeepSeek/MiMo）
- `JohnnyZ93/oai-compatible-copilot`（VS Code 插件，VS 用不了）
- LiteLLM / one-api / new-api（通用网关，太重）
差异化：纯 .NET 单文件 + NewLife.Agent 服务化 + VS 优先 + 国内供应商预设。

### 关键坑（已写入 PLAN.md 第五节）
1. Content-Type 重复追加 → DeepSeek 返回 415（参考项目 Bug #1）
2. `/api/show` 的 `capabilities` 必须含 `tools`，否则 Copilot Agent 模式不可用
3. `model_info` 的 `<family>.context_length` 决定 Copilot 侧截断
4. Copilot Agent 的工具 JSON Schema 需清洗（`$schema`/`additionalProperties` 等）
5. `reasoning_content` ⇄ Ollama `thinking`；回传上游时 DeepSeek 要求不带
6. NDJSON ⇄ SSE 转换，末帧需补 `done_reason` / `eval_count`
7. **DPAPI CurrentUser 与 Windows 服务 LocalSystem 账户冲突** → 改用 LocalMachine + entropy
8. 端口 11434 与真实 Ollama 冲突

### 关键 NewLife API 坑（后续 M2-M6 必踩，已写入代码注释）
1. **FastJson 大小写不敏感**：settings.json 用小写 `ownedBy`/`provider` 能正确映射到 `ModelOptions.OwnedBy`/`Provider`，无需改配置。
2. **绑定地址安全**：`HttpServer` 默认绑 `0.0.0.0+[::]`（全网卡）。必须显式 `Local=new NetUri(NetType.Tcp, IPAddress.Loopback, port)` + `AddressFamily=AddressFamily.InterNetwork`，否则 API Key 暴露在局域网。
3. **`JsonHelper.ToJson(obj,false,false,false)` 的 nullValue=false 会连默认值一起删**（`false`/`0`/`""` 全消失）——`stream:false` 和 `temperature:0` 会被吞。改用 `Dictionary` 逐字段构造，序列化用默认 nullValue。
4. **`XTrace.WriteLine` 用 String.Format**：格式串里写 `{(Int32)resp.StatusCode}` 这种插值语法会抛 `FormatException`。一律用 `{0}/{1}` 占位符。
5. **serve 模式（非 `-run`）**：`NewLife.Agent` 的模拟运行内部调 `Console.ReadKey()`，stdin 被重定向（后台/CI/Docker）时直接崩。自写 `serve` 子命令用 `ManualResetEventSlim` 阻塞。
6. **Content-Type charset**：`HttpContextExtensions.WriteJson` 会附加 `; charset=utf-8`，Copilot 的 Ollama 客户端可能因此 415。所有端点改走 `WriteJsonNoCharset`（自写，直接 `application/json`）。
7. **协议形态**：`/api/generate` 必须返回 `response` **字符串**（不是 `message` 对象）；`/api/show` 未知模型必须 **404**（不能伪造 capabilities）；`/api/version` 返回 `0.11.4` 规避版本门禁。

## 监听地址热重载补做（M6 backlog，本会话末段）

用户要求“单独补上”→ 实现 `settings.json` 的 `host`/`port` 变更无需重启进程（重建监听套接字）。

### 实现（Http/OllamaHttpServer.cs）
- `Start()` 抽出 `StartListener(url)`（建 `HttpServer` + `BindRoutes(server)` + `server.Start()`，**成功后才**赋 `_server`，避免半初始化实例残留）+ `StopListener()` + `BindRoutes(HttpServer)`（路由声明复用，避免重复）。
- 新增字段：`_reloadLock`（重建重入锁）、`_boundUrl`（当前实际绑定地址）、`ListenUrl` 改为 `private set`。`_settings` 去掉 `readonly`（重载后重新指向最新 `Settings` 实例）。
- `OnConfigChanged` 在 `lock(_reloadLock)` 内：`ModelRegistry.Instance.Load()` → 把 `_settings` 重新指向 `ModelRegistry.Instance.Settings`（**修正既有隐患**：`Load()` 整体替换 `Settings` 对象，原 `_settings` 会变 stale 导致 `HandleStatus` 读的 `aggregateLocalOllama`/`url` 不更新）；若 `newUrl != _boundUrl` → `StopListener()` 后 `StartListener(newUrl)`，失败则回退 `StartListener(oldUrl)` 并尽力恢复服务。
- 关键坑：`ModelRegistry.Load()` 是 `Settings = s;`（整体替换，非原地 mutate），所以旧“对比前后 `_settings.Url`”写法在对象被替换后语义已变；现统一以 `_boundUrl` 比对、以 `ModelRegistry.Instance.Settings` 为权威来源。
