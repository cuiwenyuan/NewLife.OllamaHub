## 诊断：自签证书浏览器报"未信任"（用户用文档命令部署 lanHttps 后）
- 现象：按 `docs/configuration.md` 原命令 `New-SelfSignedCertificate -DnsName "localhost","<服务器IP>"` 生成证书、装到 VS 机器后，浏览器打开 HTTPS 仍报未信任。
- **根因 1（最关键）**：PowerShell `New-SelfSignedCertificate -DnsName` 把 `<服务器IP>` 当作 **dNSName** 写进 SAN，而非 **iPAddress** 型 SAN。浏览器用 `https://<IP>:11435` 访问时查的是 iPAddress 条目，找不到 → `NET::ERR_CERT_COMMON_NAME_INVALID`（表现像"未信任/连接不是私密连接"）。该 cmdlet 无原生 IP SAN 参数，必须用 `-TextExtension @("2.5.29.17={text}IP Address=<IP>&DNS=localhost")`。
- **根因 2**：自签证书须导入**访问机器的"受信任的根证书颁发机构"**（非"个人"/"中间证书"）；服务端 `CurrentUser\My` 生成的证书客户端不会自动信任，需导出公钥 `.cer` 拷到客户端手动装；Firefox 不读系统存储需单独导入。
- **修正**：重写 `docs/configuration.md` 证书段落——推荐 `mkcert -install` + `mkcert -p12 hub.pfx <IP> localhost`（自动进系统信任库、SAN 正确）；保留 PowerShell 方案 B 用 `-TextExtension` 显式写 iPAddress；新增客户端导入位置、重启、Firefox 例外、SAN 验证（`certutil -dump`）说明。
- 补充：VS 局域网接入另有免证书捷径——启用 `lanHttp`(11436 明文) + VS 先填 https 保存再改 `ConfiguredBringYourOwnModel_v1.json` 为 http（见文档 71-80 行），可完全绕开自签证书信任难题。
