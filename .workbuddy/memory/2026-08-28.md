# 2026-08-28（再续2）修复 DeepSeek 工具调用 400 missing field tool_call_id

- **现象**：用户调用 DeepSeek（Copilot Agent 模式、带工具调用）报错 `上游 deepseek 返回 400：... messages[4]: missing field tool_call_id`。
- **根因（三层叠加）**：① `OpenAiAdapter.OpenAiMessage` 原本无 `tool_call_id` 属性 → 入站 `/v1/chat/completions` 的 `tool_call_id` 未被解析；② `OllamaHttpServer.ToOllamaRequest`（OpenAI→Ollama 转换）未透传 `tool_call_id`；③ `OpenAiAdapter.BuildOpenAiRequest` 构造上游消息时，`role:"tool"` 只写 `role`+`content`，从不输出 `tool_call_id`。DeepSeek（OpenAI 兼容）强制要求 tool 消息带 `tool_call_id` 且与前置 assistant `tool_calls[].id` 对应，缺失即 400。
- **修复**：① `OpenAiMessage` 加 `tool_call_id` 属性；② `ToOllamaRequest` 透传 `tool_call_id`；③ `BuildOpenAiRequest` 对 tool 消息输出 `tool_call_id`（优先入站值，缺失时按最近 assistant 的 `tool_calls` 顺序合成 `call_0/call_1…` 并配对），新增 `NormalizeToolCalls` 辅助确保 assistant `tool_calls` 每条有 id。改动仅限 OpenAI 兼容链路（openai 上游）；anthropic/gemini 走各自 schema 未动。
- **验证**：`dotnet build -c Release` 0 错误；`self-test` 271→**274/0**（新增 `CheckToolCallIdRequestPassthrough` 3 条断言全 PASS）。
- 改动文件：`src/NewLife.OllamaHub/Core/OpenAiAdapter.cs`、`src/NewLife.OllamaHub/Http/OllamaHttpServer.cs`、`src/NewLife.OllamaHub/Commands/SelfTest.cs`、`ChangeLog.md`（v1.3.3 加修复条目）。
