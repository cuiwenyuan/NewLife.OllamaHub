02 / 08
痛点

GitHub Copilot 的模型，
你好像只有两个选择

  • A用官方模型：体验稳，账单肉疼
  • B自己折腾：Docker、代理、协议转换，劝退

那有没有第三条路？
有——让 GitHub Copilot 以为你在连本地 Ollama。

03 / 08
解法

一个 exe，
伪装成本地 Ollama

  • 1在本机起服务：127.0.0.1:11434
  • 2客户端（VS Code / Visual Studio）以为在跟 Ollama 说话
  • 3请求被转发给 DeepSeek / GLM / Kimi 等上游
不用改客户端 · 不用装依赖
04 / 08
原理

一次请求，是这样走的

GitHub CopilotVS Code / Visual Studio 两端，以为在调用本地 Ollama 模型
↓
OllamaHub　127.0.0.1:11434接收 Ollama 协议，翻译成上游协议
↓
DeepSeek / 通义千问 / Kimi / GLM …OpenAI · Anthropic · Gemini · Responses 多协议适配

06 / 08
上手

三步就能跑起来

1
下载单文件 exe，按运行时选版本
.NET 8 / 10 双版本，不写注册表、不装第三方依赖
2
填 API Key
菜单里 setkey，或直接改 settings.json
3
在 VS Code / Visual Studio 里选 Ollama
模型提供程序选 Ollama，Endpoint 填本机 11434，模型列表直接拉出来
07 / 08
进阶玩法

不只是本地自嗨

  • ◆局域网共享：一台机器当团队模型网关，HTTP / HTTPS 双通道
  • ◆多协议适配：OpenAI / Anthropic / Gemini / Responses
  • ◆自带自检：306 项断言，升级不怕踩雷
  • ◆可装成服务：开机自启，后台常驻
